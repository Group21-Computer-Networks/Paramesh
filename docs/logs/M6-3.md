### 2026-10-18 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
- Asked the person: the card's `127.0.0.1:7070` and "served by `pmd`" against the status API
  on `--http-port` (default 47002). Answer: the same server, a new route: `pmd` serves the page
  at `/` of its status port, and `--http-port 7070` gives `127.0.0.1:7070`. That needs a
  small route in `src/pmd/`, outside the card.
- `tools/dashboard/index.html` (new): one page, no library, light and dark. It reads
  `/v1/events` (`EventSource`) for each second's rates, and `/v1/peers`, `/v1/jobs` and each
  job's `/pages` once a second and on every join, leave, job start and end. Shows the peers;
  the jobs on the node with the same columns as `pm top` (slots, faults per second, MB per
  second in and out, p50 and p99); page ownership as a grid of the job's segments (home here,
  held M, held S); and, while a peer is leaving, a bar of how many of the segments homed on
  it, as far as this node sees them, have moved.
- `src/pmd/`: `GET /` serves the file at `--dashboard FILE`, read at each request; by default
  `tools/dashboard/index.html` of the source tree the program was built in (four directories
  above the executable's), set in `open()`. 404 with a hint when it is not there.
- Checked by hand in the built-in browser: three daemons, node 1 with `--http-port 7070`, the
  test program running until told to stop. The page at `http://127.0.0.1:7070/` and `pm top
  --http-port 7070` at the same second: both 2,684.3 faults/s, 1.79 MB/s in, 1.79 MB/s out,
  p50 4 us, p99 4,096 us, 16 slots. With every daemon seeding the others the peers table
  lists nodes 2 and 3. `pm leave` on node 3 finished in well under a second, before a beacon
  carried its "leaving" flag, so the bar had no time to show; its drawing was checked in the
  page instead: a leaving node with 3 segments, then 2 moved: "segments moved 0 of 3", then
  "2 of 3" at 67%, then gone once nobody leaves.
- Tests (`tests/unit/pmd_test.cpp`): "pmd serves the dashboard at / of its status port, a page
  that reads the API" (the page, its `EventSource` and API paths, no script from elsewhere; a
  missing file is 404); `--dashboard` in the command-line test.
- First test run: the page was not found, because the test daemon builds its configuration
  without the parser where the default was set; the default moved to `open()`.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **The page is read from disk at each request,** not built into `pmd`: no build-file change,
  and an edit shows on reload. Its default is found from the executable's place in the build
  tree; an installed `pmd` passes `--dashboard`.
- **The migration bar** counts segments homed on a leaving peer among those this node holds
  or homes (the pages summary), so it shows only this node's part of the move; a leave that
  ends within a beacon is not seen at all.
- **Rates come from the event stream** when it has them, else from the jobs snapshot; the two
  are the same second.
