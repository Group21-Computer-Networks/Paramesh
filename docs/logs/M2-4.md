### 2026-10-09 — session 2: the manager, the waiting side, and tests

- `src/wire/`: `SyncPayload` (id, one 16-bit word, six reserved bytes) with its encoder and
  decoder. One struct serves all five messages: the word is the thread index in `LOCK_ACQ`,
  `LOCK_REL` and `BARRIER_ENTER`, and the status in `LOCK_GRANT` and `BARRIER_RELEASE`.
- `src/rt/sync.h`, `src/rt/sync.cpp`: class `Sync`.
  - Launcher side: a table of locks, each with a holder and a first-in-first-out queue; a
    table of barriers, each with a count and its waiters; a count of outstanding work.
  - Every process: `lock`, `unlock` and `barrier_wait` for its threads. A worker sends the
    request and sleeps until the answer; the launcher's own threads ask the table directly.
  - `on_frame` takes the five messages on the network thread and never waits.
- `tests/unit/rt_test.cpp`: nine new cases with a fake transport and a fake host;
  `tests/unit/wire_test.cpp`: one for the payload.
- `src/rt/` is now a static library (it had no source file before).
- A slip, put right before pushing: a failed script left a commit named "wip" on the branch;

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **One class, `Sync`, not yet behind `Runtime`.** `rt/runtime.h` is implemented piece by
  piece over five tasks; this is the lock and barrier piece, and the class that implements
  `Runtime` will hold one. `Sync` takes the caller's thread index as an argument, because
  worker threads and their indexes arrive with M3-2.
- **One counter numbers locks and barriers,** so a lock handle used as a barrier is
  `BAD_HANDLE`, not somebody else's barrier.
- **Request numbers from the upper half** (bit 63 set). The protocol wants a number the
  sender has not used on that connection, `src/lib/` numbers its page requests from 1, and
  `RuntimeHost` offers no shared counter. Marked `ponytail:` in `sync.h`.
- **The header's `epoch` is 0 in these frames:** `RuntimeHost` does not give the runtime the
  epoch, and the epoch rule concerns page requests and `ATOMIC_OP` only.
- **What correct processes never do ends the job** with status `PROTOCOL`: a release by a
  thread that does not hold the lock, a grant that answers no request, a lock request sent to
  a worker, a payload of the wrong size. None is guessed around.
- **`unlock` and a double `lock` are refused locally,** as `LOCK_REL`'s text in the protocol
  says, so no message is sent for them.
- **`holds_lock(node, thread)`** is the question G13 needs answered (M0 gate: a chunk run
  again while its thread holds a lock ends the job). The code that runs chunks again does not
  exist yet; see Deferred.
- **One mutex and one condition variable** for the whole class. The network thread takes the
  mutex in `on_frame`; application threads hold it for a few instructions and never while
  touching shared memory, so the rule on blocking holds.

**Done-when: unit tests on the lock and barrier logic with a fake transport.**
`build/dev/tests/unit/unit_rt_test`: 11 cases (9 new), 127 assertions, all passed.

| Case | What it shows |
| --- | --- |
| handles | only the launcher makes them; each is new; zero is never one |
| first come, first served | four waiters on one lock are granted in arrival order, each with its own request number; a second lock has its own queue |
| barrier | nothing until the count is reached, then every waiter is released; the barrier works a second time |
| `BAD_HANDLE` | an unknown id, a barrier used as a lock, a lock used as a barrier |
| the launcher's own threads | no message is sent for them; they share the queue with workers |
| a worker's lock | the thread sleeps from `LOCK_ACQ` to `LOCK_GRANT`; `unlock` sends `LOCK_REL`; a double lock and a foreign unlock are refused without a message |
| a worker's barrier | the thread sleeps until `BARRIER_RELEASE` |
| `wait_all` | returns at once with nothing outstanding; sleeps until the count is zero; `STATE` on a worker |
| what cannot happen | five cases each end the job (a child process exits through `abort_job`) |

`unit_wire_test`: 7 cases, 98 assertions; the new one checks the payload against bytes
written out from the protocol document, and rejects a short and a long one.
