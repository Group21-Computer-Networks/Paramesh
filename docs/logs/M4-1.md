### 2026-10-13 — session 2: discovery

- `src/wire/`: `HelloPayload` (with its ledger totals, which M5 fills) and `ByePayload`.
- `src/pmd/peers.h`, `.cpp`: `PeerTable`, pure: a beacon and the time go in. A new node is
  added; a known one refreshed; the same ID with another instance from the same address is a
  restart and replaces the entry; from another address it is a clash and the first keeps the
  ID; this daemon's own beacon is recognised by its instance. Suspect after 3 s of silence,
  removed after 5 s; `BYE` removes at once.
- `src/pmd/pmd.cpp`:
  - a UDP socket on the discovery port; the group 239.77.77.77 is joined on every interface
    that is up and can multicast, loopback aside, or only on `--iface`; TTL 1, and loopback
    delivery on so that daemons on one machine hear each other;
  - every second a `HELLO` on each of those interfaces and to every seed of `--peers`, and
    peers silent too long leave the table; `BYE` when the daemon stops;
  - the node ID: `--node-id`, or the one kept in `<state-dir>/node_id`, made at random on the
    first run;
  - `GET /v1/peers` on 127.0.0.1 (`--http-port`, default 47002): this node, its peers with
    their state and capacity, and any ID clash seen;
  - new flags `--discovery-port`, `--http-port`, `--no-multicast`, `--iface`; a `--peers`
    entry may carry the discovery port as well; `--node-id` is no longer required.
- `src/tools/pm.cpp` and the `pm` executable: `pm status [--http-port N]`, a small HTTP client
  of the daemon's API, prints a table.
- Tests in `tests/unit/pmd_test.cpp` and `wire_test.cpp`; results under Verification.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Silence is counted in time,** not in beacons: suspect after 3 s, removed after 5 s, since a
  beacon is due every second.
- **One report for each clash,** remembered by node and instance, logged as `node_id_clash` at
  `warn` and listed in `GET /v1/peers`.
- **The daemon still asks for workers in the order of `--peers`.** HELLO now carries free
  capacity, but choosing peers by it belongs with admission (M4-4). A peer known only from
  multicast is therefore not asked yet; in `docs/TODO.md`.
- **HELLO's capacity fields are partly empty:** `cap_ram`, `free_ram` and the spill fields are
  0 and `free_cores` is the cap, until M4-2 counts them. `jobs` is the number of jobs launched
  here.
- **`pm status` speaks HTTP by hand** (about thirty lines): the vendored HTTP library may be
  included only by the platform adapters, and the platform has a server, not a client.
- **The status API listens on loopback only:** it has no login.
