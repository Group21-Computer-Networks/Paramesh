### 2026-10-18 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
- `tools/dissector/paramesh.lua` (new): a Lua dissector for Wireshark. The 36-byte header as
  filterable fields (`pmsh.opcode`, `pmsh.job`, `pmsh.src`, `pmsh.page`, ...), the flags by
  name, and the payload of every opcode in docs/PROTOCOL.md, each described as a list of
  fields read by one walker (integers, IPv4, hashes, `str16`, reserved bytes, counted arrays,
  pages that carry 4,096 bytes unless `ZERO_PAGE`, `SEG_MIGRATE`'s entries). A payload shorter
  than its layout, or with bytes left over, is flagged malformed (`pmsh.malformed`).
  Discovery on UDP 47000, daemon control on TCP 47001, and the data plane, whose ports are
  chosen at run time, by a heuristic on the magic; TCP frames are reassembled by
  `payload_len`. The local link is a Unix socket and is not captured; its messages are in the
  dissector all the same. The tables were written from the protocol document's (extracted by
  a one-off script, not kept).
- `tools/dissector/capture.sh` (new): a three-node run (default `matmul 256 1`) in network
  namespaces (`tests/multi/netns.sh`), captured with `tcpdump` on their bridge, then read with
  `tshark` and the dissector: frames decoded, by opcode, and how many malformed.
- Problems on the way, in the script: inside the namespace `tcpdump` could not be signalled
  ("Permission denied"), so the script hung and four `tcpdump` processes from those runs kept
  writing the same file, which corrupted it (records from 2,398 on); they cannot be killed
  without `sudo` and were reported to the person. Now the script ends its `tcpdump` by taking
  its bridge away, and writes a new file each run. `tcpdump` needs `-Z root` there. And
  Wireshark will not run a Lua dissector as root, so the capture is read outside the
  namespace, as the user.
- `tshark` was not installed; the person installed it (4.2.2).
