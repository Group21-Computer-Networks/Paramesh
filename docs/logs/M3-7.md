## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **A worker takes the launcher's node ID from the job ID** (its high half, as `L_RUN_OK`
  defines it): the environment of section 10 gives a worker the launcher's address but not
  its ID, and the transport needs the ID to know which side connects.
- **A thread for the local socket.** The network thread may wait only on epoll and the
  transport has no way to add a descriptor, so one more thread blocks on the socket to the
  daemon. It only ever calls `abort_job`.
- **A job whose daemon goes away ends** with `PMD_LOST`, as the M0 gate settled ([GATE P9]).
- **`ram_weight` is ignored for placement,** as before: every member weighs the same until
  daemons commit memory (M4-2).
- **`JOIN_JOB` announces port 0 when the port was chosen by the system:** the transport is
  told its own port before it listens. Nothing reads that field yet; in `docs/TODO.md`.
- **The counter is now `adds` tasks spread over the job,** not "each node adds N times": tasks
  go to whichever node asks. The program prints how many adds each node made.
- **The counter's lock phase may not be run twice,** unlike what `paramesh.h` asks of a task;
  the program says so. It matters only once nodes can leave (M4).
- **The launcher stays in `pmrun`'s process group.** A Ctrl+C typed at a terminal therefore
  reaches the launcher too, which dies of it at once, and the workers end with "node lost".
  A signal sent to `pmrun` alone takes the orderly path: `L_ABORT`, then `JOB_END` to every
  node. Either way no process is left. Giving the launcher a group of its own would make
  the first case orderly but take the terminal's input away from the program.
- **`tools/bench/matmul.sh` still starts jobs with `run_local.sh`:** it is not on this card,
  and `PARAMESH_PEERS` still works.
