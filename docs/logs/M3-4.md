### 2026-10-09 — session 2: the daemon and its tests

- `src/wire/`: payloads for `SPAWN_REQ`, `SPAWN_OK`, `SPAWN_DECLINE`, `L_REGISTER`, `L_QUOTA`.
- `src/pmd/frame_io.h`, `.cpp`: one frame at a time on a stream socket, blocking. The daemon
  uses it to reply; the tests use it on both channels.
- `src/pmd/pmd.h`, `.cpp`: class `Pmd` and `pmd_parse_args`. One thread and one `poll` loop
  over the control listener, the local socket and every connection.
  - `SPAWN_REQ`: read the file at `path`, compare its SHA-256 with the launcher's, and decline
    with `NOT_FOUND` or `BINARY_MISMATCH`; otherwise start the program in the launcher's
    working directory, with its arguments and the environment of `docs/PROTOCOL.md` section 10.
  - `L_REGISTER` from that process: `SPAWN_OK` goes to the daemon that asked, with the
    worker's data port and this node's cap; the process gets `L_QUOTA` with `--cap-cores`.
  - A worker that exits before it registers: `SPAWN_DECLINE`, status `INTERNAL`.
- `src/pmd/main.cpp` and the `pmd` executable, with `--help`, the five flags, and a clean stop
  on SIGINT or SIGTERM (the socket file is removed).
- `tests/unit/main.cpp`: a test executable may now also be started as a helper process by its
  own tests. `pmd_test` uses it: the daemon starts the test executable itself as the worker.
- State: Done-when met. What the daemon does not do yet is under Deferred.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Only the receiving side of `SPAWN_REQ` is here.** Sending it, choosing peers and admitting
  a job belong to M3-5 (`pmrun` and `L_RUN_REQ`, `L_ADMIT_REQ`). `--peers` is parsed and kept
  for it.
- **The daemon reads the executable and hashes it itself,** as the protocol says, and checks
  the hash again in the worker's `L_REGISTER`. A worker whose own hash differs is killed.
- **A worker inherits the daemon's environment without its `PARAMESH_` variables,** except
  `PARAMESH_CFG_*`, then gets the five of section 10. Tunables therefore pass through from
  the daemon's own environment until it reads a configuration file.
- **`ram_commit` and `spill_commit` are 0 in `SPAWN_OK`:** caps on memory are M4-2.
- **The quota is the same for every job:** `--cap-cores`, as the card says.
- **One thread, blocking replies.** The few frames this daemon sends are small. Marked
  `ponytail:` where a queue would go.
- **Only the daemon's own children are collected** (`waitpid` on each, not on any child), so
  it can run inside a test process without taking other tests' children.
- **`frame_io` lives in `src/pmd/`.** `pmrun` (M3-5) and the job process (M3-7) need the same
  two functions; M3-7 can move them below `src/lib/` if it wants them there.
- **Flags are `--name value`,** always in pairs. No configuration file yet: this daemon has no
  tunable to read from one.
