## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
These are choices of form inside the card. Every choice of meaning is a proposal under
Questions, not a decision.

- **Names from the documents are kept exactly:** `pm_init`, `pm_finalize`, `pm_malloc`,
  `pm_parallel_for`, `pm_wait_all`, `pm_touch`, `pm_atomic_add`, `PM_TASK`, `pm_lock_t`
  (plan), `pm_lock_create`, `pm_lock`, `pm_unlock`, `pm_register_task`, `pm_config`,
  `pm_task_ctx`, `pm_barrier_t` (Build Plan sketch).
- **Constants are plain literals, not casts,** after the cast form failed a C++ build with
  `-Wold-style-cast`.
- **Error codes are an `enum` and functions return `int`,** the usual C form, so a new code
  never changes a signature.
- **No reserved or size fields in the structs.** Every node of a job runs the same binary
  (the plan checks its hash), so there is no cross-version layout to protect.
- **`PM_TASK` marks its four parameters unused.** Otherwise a task that ignores `ctx` fails
  to compile in any program that treats warnings as errors, including ours.
- **A permanent test rather than a one-off compile,** so CI keeps proving the header is C11
  and C++20 after it is frozen and when M3-1 edits the macro body.
- **One `NOLINTBEGIN`/`NOLINTEND` pair in the header** rather than loosening `.clang-tidy`
  for the whole tree: C naming, `typedef`, `<stdint.h>` and macros are right here only.

## Questions and blockers

<!--
Each item starts with [open] or [answered YYYY-MM-DD by <who>], followed by the question and,
once answered, the answer. M0 drafting tasks may also use [for gate] for a Still-open point
drafted for the person to decide at the M0 gate. Write "None" if there are none.
-->
Each item names the Still-open point it belongs to, what the draft proposes, and the
alternatives. The `G` numbers match the `[GATE Gn]` tags in `include/paramesh.h`.

- [for gate] #1, G1 — `pm_init(int* argc, char*** argv, const pm_config* cfg)`, returning on the
  launcher and never on a worker. Proposed as in the Build Plan sketch, with `argc`/`argv`
  reserved and unused, since the plan sends settings by environment variable. Alternative:
  `pm_init(const pm_config* cfg)`.
- [for gate] #1, G2 — `pm_config` fields. Proposed: `region_bytes` (0 = size given at launch, else
  4 GB) and `threads_per_node` kept only as an upper bound under pmd's quota. Two real
  conflicts to settle: (a) M4-4 refuses an oversized job "before any process starts", but the
  region size is first known inside the launcher's `pm_init()`. Draft: the launcher starts,
  its `pm_init()` asks pmd, pmd admits or refuses before any *worker* starts, and `pm_init()`
  returns `PM_ERR_REFUSED`. Alternatives: a `pmrun --region` flag and no field; or both, the
  field checked against the flag. This also shapes M0-5. (b) Whether `threads_per_node` should
  exist at all now that pmd pushes the quota; alternative: remove it.
- [for gate] #1, G3 — the task function and `pm_task_ctx`. Proposed parameters
  `(const pm_task_ctx* ctx, uint64_t lo, uint64_t hi, const void* arg)` as in the Build Plan,
  and ctx fields `node`, `thread`, plus a new `arg_len`. `PM_TASK(name)` fixes those four
  parameter names, gives the function internal linkage, and a name registered twice stops the
  program in `pm_init()`. Alternative: no `arg_len`.
- [for gate] #1, G4 — `pm_parallel_for` is kept as in the Build Plan sketch, and
  `pm_parallel_for_data(..., const void* data, size_t stride)` is **added**. Reason: M3-2 cuts
  ranges into "page-aligned chunks" and M3-3 prefers chunks "whose pages are homed on the asking
  node", but an index range alone names no pages. Alternatives: add the two parameters to
  `pm_parallel_for` itself; or drop page alignment and affinity for ranges with no array and
  have M3-2/M3-3 reworded. The 1 KB argument limit (`PM_TASK_ARG_MAX`) is from the Build Plan
  sketch only.
- [for gate] #13, G5 — the unit of work in a chunk for valuing credit. Proposed: the number of
  indexes in the chunk (`hi - lo`), so the node's own cost model is CPU time per index of that
  task, and the API needs no call. Alternative: the task declares its work, which would add
  either a parameter to `pm_parallel_for` or a call such as `pm_task_work(ctx, units)`.
- [for gate] #1, G6 — `pm_lock_t`. Proposed: a struct holding one 64-bit ID, 0 never valid,
  storable in shared memory; created only on the launcher (the HLD has no create opcode);
  FIFO, not recursive, no destroy call; `pm_lock`/`pm_unlock` return `int` where the Build Plan
  returned `void`. Alternatives: a bare `uint64_t`; creation from tasks; `void` returns with a
  misuse aborting the job.
- [for gate] #1, G7 — barriers. Proposed: `pm_barrier_t`, `pm_barrier_create(uint32_t count)`,
  `pm_barrier_wait(pm_barrier_t)`, modelled on POSIX. The plan (FR-5.3, M2-4), the HLD opcodes
  and the Build Plan's handle type all name barriers, but no available document gives a
  function. Alternative: `pm_wait_all()` is the only barrier and these three are removed.
- [for gate] #1, G8 — `pm_touch(const void* p, size_t n, pm_access access)` returning `int`.
  The Build Plan had `void pm_touch(void* p, size_t n)`. The access is added because a buffer
  the kernel writes (as in M1-8's `read()`) needs write access, while one it only reads should
  not take the page from other readers. Alternative: the two-parameter form, always fetching
  for writing.
- [for gate] #1, G9 — error codes. Proposed: `PM_OK` and eight negative codes (`INVALID`,
  `STATE`, `NOMEM`, `UNKNOWN_TASK`, `PLATFORM`, `CONFIG`, `REFUSED`, `NETWORK`), a new
  `pm_strerror()`, and `pm_finalize()` returning `int` rather than `void`. No earlier document
  names an error code. Not covered here: the exit status of a process when its job aborts,
  which no document states; it belongs with the abort path in M0-5.
- [for gate] #1, G10 — `uint64_t pm_atomic_add(uint64_t* addr, uint64_t delta)` as in the Build
  Plan, returning the old value, wrapping modulo 2^64. Proposed: an address outside the region
  or not a multiple of 8 aborts the job, because the return value cannot carry an error.
  Alternative: `int pm_atomic_add(uint64_t* addr, uint64_t delta, uint64_t* old)`.
- [for gate] #1, G11 — `pm_malloc`. Proposed: launcher only (the Build Plan cuts `pm_malloc`
  from workers); an allocation of a page or more is page-aligned and owns its pages, a smaller
  one is 16-byte aligned; no `pm_free` (the Build Plan says it "can be a no-op").
  Alternative: declare `pm_free` as a documented no-op.
- [for gate] #1, G12 — source check. The plan says the API is "exactly as in the SRS", but the
  SRS v0.5 and Doc 1 are not on this laptop. The names here come from the plan, the HLD and
  the Build Plan sketch. Someone holding the SRS should compare its API list with this header
  before approval, or put the SRS beside the other PDFs for the agent to do it.
- [for gate] G13, for M0-6 rather than this file — a task that holds a lock when its node leaves
  is run again elsewhere (FR-3.4), and nothing says what happens to the lock it held. The
  header only says a task must release its locks before returning.
