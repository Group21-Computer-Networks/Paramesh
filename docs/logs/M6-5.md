### 2026-10-18 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
- `tools/bench/evaluate.sh` (new): three nodes in network namespaces (`tests/multi/netns.sh`),
  fresh daemons for each run, `matmul 256 1` by default, one results file per experiment in
  `build/results/`: `impairment` (every delay 0, 1, 5, 10, 25, 50 ms; jitter 0 or 25% of the
  delay, none at 0 ms; loss 0, 1, 2, 5%: 44 runs, set with `tc qdisc change` on each node's
  link), `outofcore` (`--cap-ram 1M` on each node, a spill budget of 64 MB, `matmul 512`: a
  6 MB region over 3 MB of caps) and `histogram` (one run without impairment: the merged
  fault-latency buckets). Each row: run time, faults, faults per second, MB per second
  received, p50 and p99 fault latency (bucket upper bounds, `>16384` for the open-ended last),
  retries, aborted.
- First the counts were polled from `/v1/jobs`, but `matmul 256` ends in 0.05 s, before its
  first once-a-second report, and `pmd` forgets a job when it ends. Asked the person; approved
  to extend the end-of-job log line instead: `job_pages` now also has `faults`, `sent` and the
  16 `latency` buckets (`src/lib/job.cpp`, outside the card), which the script sums over the
  launcher's output and the daemons' logs: exact totals for any run. `lib_test` checks the
  fields are there.
- The histogram's buckets end at 16 ms (L_STATS, M6-1): from 5 ms of added delay the slow
  faults, and from 10 ms all of them, fall in the last bucket, so the percentiles there only
  say ">16 ms". Noted, not changed: the bucket layout is in the frozen protocol.
