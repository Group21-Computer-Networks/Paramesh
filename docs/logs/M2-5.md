### 2026-10-09 — session 2: the path of one add, and its tests

- `src/wire/`: `AtomicOpPayload` (24 bytes: offset, operand, op 1, reserved) and
  `AtomicResultPayload` (16 bytes: offset, old value).
- `src/lib/job.cpp`, the path of one `pm_atomic_add(addr, delta)`:
  1. The calling thread checks the address, takes a request number, queues the add for the
     network thread and sleeps.
  2. The network thread sends `ATOMIC_OP` to the page's home. If that is this node, the frame
     goes through the job's own queue, like every other frame a node sends itself.
  3. The home hands the request to the home machine (M2-1), which first invalidates every read
     copy or takes the page back from its owner, then returns one "apply atomic" action.
  4. The job carries that out on the home copy: zeros for a page never written, add, store,
     and `ATOMIC_RESULT` with the old value.
  5. The result wakes the calling thread.
- Tests in `tests/unit/lib_test.cpp` and `tests/unit/wire_test.cpp`; results under Verification.
- Nothing in `src/coh/` or `src/rt/` changed; see Decisions.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Nothing was added to `src/coh/`:** the home's part ("takes the page back first", then one
  apply-atomic action) was built and tested with the rest of the home machine in M2-1, and
  fuzzed in M2-6.
- **Nothing was added to `src/rt/` either.** The frozen `Runtime::atomic_add` belongs there,
  but the runtime cannot send a frame to its own node: `Transport::send` refuses, and
  `RuntimeHost` has no in-process delivery, while the home of the number is often the caller.
  The job process has both paths already, so the add lives in `job.cpp`, about 70 lines.
  When M3-2 assembles the class behind `rt/runtime.h`, its `atomic_add` has to reach this
  code; in `docs/TODO.md`.
- **The number is added in the program's own byte order,** with `memcpy` on the home copy:
  that is how the program's threads read it. Every node of a job runs the same binary.
- **A bad address ends the job with status `INTERNAL`** and a message naming the function,
  as `paramesh.h` says it must; so does a call before `pm_init()`, which prints and exits.
- **`ATOMIC_OP` is under the reply timer,** as the protocol has it for every request not on
  its list of exceptions.

**Done-when: concurrent adds from three simulated nodes sum exactly.** `unit_lib_test`, case
"concurrent atomic adds from three processes sum exactly": passed, 2.3 s. Three processes on
localhost each add 1 to seven numbers, 200 times each, all at the same time; the numbers are
at the start of seven different segments, so their homes differ. Every eighth round a node
also reads the number the ordinary way and writes a neighbour in the same page.

| Check | Expected | Result |
| --- | --- | --- |
| Each of the 7 numbers at the end | 600 | pass |
| Each node's own neighbour, written the ordinary way | 25 | pass: nothing lost when the home took the page back |
| The values one node gets back for one number | always growing | pass |
| A read straight after an add | more than the value the add returned | pass |
| All three processes | exit 0, nothing on stderr | pass |

Case "pm_atomic_add returns the old value, and an address it cannot use ends the job", a job
of one node, which is the home of everything: the first add to an unwritten page returns 0;
after an ordinary write the home takes the page back from itself; adding 2^64 - 1 subtracts
one; the last number of a page works; an address that is not a multiple of 8, and one outside
the region, each end the process with status 1 and
`job 44 aborted: pm_atomic_add: the address is not an 8-byte-aligned number in the shared region`.

`unit_wire_test`: the two payloads against bytes written out from the protocol document; a
wrong op, an odd offset and a wrong length are rejected.

Repeats: the atomic cases 12 times in the dev build, 6 times each under gcc ASan and clang
UBSan, and the three-process case 12 more times after the last change: 0 failures.

Quality gate: all eight compiler and sanitizer builds pass, 15/15 tests (14/14 under TSan), no
warnings; clang-tidy exit 0; clang-format clean.
