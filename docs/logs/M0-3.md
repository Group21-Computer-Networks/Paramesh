## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **`JsonValue` is a small variant of our own** (null, bool, int64, double, string, array,
  object), so no caller sees a third-party type. Unsigned values above INT64_MAX are not
  representable; marked `ponytail:` in the adapter.
- **One registry per capability, keyed by name, seeded with the built-in adapter.** Replacing a
  library is an adapter class plus one `platform_register` line. A maker receives the
  capabilities built before it, which is how the logger gets the clock and the JSON codec.
- **The configuration loader is not chosen by name:** it is needed before there is a
  configuration.
- **Log time is wall-clock nanoseconds since the epoch,** an integer; exact and sortable.
- **Left out until a task needs them** (each marked `ponytail:` where it would go): HTTP
  methods other than GET and server-sent events (M6-1), a faster CRC (M6-5 if it shows),
  retrying a short log write, typed configuration getters.

All local, 2026-10-07 (GCC 13.3.0, Clang 18.1.3).

**Done-when, part 1: CRC-32C and SHA-256 match published test vectors.**
- CRC-32C, RFC 3720 appendix B.4: 32 zero bytes → `8A9136AA`; 32 `FF` bytes → `62A8AB43`;
  `00`..`1F` → `46DD794E`; `1F`..`00` → `113FDB5C`; and the check value for "123456789" →
  `E3069283`. All five match.
- SHA-256, FIPS 180 examples: "abc" → `ba7816bf...15ad`; "" → `e3b0c442...b855`; the 448-bit
  message → `248d6a61...06c1`. All three match.

**Done-when, part 2: a second dummy adapter is selected by configuration name with no change
to calling code.** The test registers a `DummyHasher` as "dummy", parses
`platform.hasher = dummy` with the configuration loader, and calls the same `hash_of_abc()`
function on both platforms: the default gives the real digest, the configured one gives the
dummy's. An unregistered name gives `Errc::kNotFound`.
