- **The rows marked M4 are built now** (`EVICT`, `BUSY_RETRY`, `REDIRECT`, `RESEND`, all of
  `M→I`): the card says "complete" and asks for a test of every node transition. Nothing
  raises those events before M4. The same choice as in M2-1.
- **"Wait for acknowledgement, zap" is the eviction path,** as the document's `[DECIDED]` note
  under the table says: `FETCH_INV` discards in the same step as it sends, and a page in
  `M→I` is discarded only on `WRITEBACK_ACK`, `INV` or `FETCH_INV`. The fourth test checks
  exactly that over every event.
- **The current request is derived, not listed per row:** set by a send, cleared when the next
  state is stable, kept otherwise. This gives the two cases the document spells out (the
  `UPGRADE_REQ` outliving an `INV`, the `WRITEBACK` outliving a `FETCH`) without a flag.
