## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
Choices of form inside the card. Every choice of meaning is a proposal under Questions.

- **One frame format on all four channels,** the local socket included, so `src/wire/` has a
  single codec and the dissector a single header. The HLD already says the three network
  channels share the header.
- **Every message has a field table with offsets and a stated size,** so the document can be
  checked mechanically and M1-1 can write decoders and fixed byte-sequence tests from it.
- **Opcode values grouped by the HLD's nine groups** (0x0_ discovery, 0x1_ control, 0x2_
  membership, 0x3_ page requests and replies, 0x4_ home to holder, 0x5_ tasks, 0x6_
  synchronisation, 0x7_ leave, 0x8_ to 0xA_ local), leaving room in each.
- **Reserved bytes pad most payloads to a multiple of 4,** and are sent as zero, so fields
  can be added later without moving the others.
- **Sequences are in the document, transitions are not.** The order of messages for start,
  leave, join and abort is needed to define the payloads; what each node does in each state
  is M0-6's.

## Questions and blockers

<!--

- [answered 2026-10-06 by Amirishetty Sai Vignesh] (M0-4's G2, asked before starting because
  it decides the launch sequence in this document.) How is a job's region size admitted:
  through the launcher's `pm_init()`, or through a `pmrun --region` flag? Answer: through
  `pm_init()`. The launcher process starts first, its `pm_init()` sends the region size to the
  local pmd, and pmd admits or refuses before any worker is spawned; `pm_init()` returns
  `PM_ERR_REFUSED` on refusal. Consequence the person accepted: M4-4's "refused before any
  process starts" becomes "before any worker starts". That sentence is in `docs/PLAN.md`, which
  only the person edits; it is to be recorded with the gate answers.
- [answered 2026-10-07 by Amirishetty Sai Vignesh] (M0-4's G12.) Should the API and the protocol
  be cross-checked against the SRS? Answer: no. "Do not read that SRS, just follow the LLD plan
  and HLD plan I gave you." The sources are `docs/PLAN.md` and the HLD only.
- [for gate] #2, P1 — payloads and opcode values. The HLD gives neither, apart from the page
  payload, which is kept exactly (page ID then 4,096 bytes; a full page frame is 4,140 bytes).
  Two opcodes are added: `SPAWN_DECLINE`, because the plan has each asked peer "accept or
  decline" and the HLD has only `SPAWN_OK` (alternative: a status field in `SPAWN_OK`); and
  `SEG_MAP_ACK`, because without it the launcher cannot tell when the mesh is complete and a
  leaver cannot tell when it is safe to close (alternative: none found that is safe).
- [for gate] #3, P2 — `HELLO`. Proposed: an instance number (detects restarts and ID clashes),
  control port, flags, RAM cap and free RAM, spill budget and free spill, core cap and free
  cores, job count, then up to 7 entries of raw totals per peer: chunks completed and
  segment-seconds hosted, in both directions, as 64-bit counts. At most 300 bytes.
  Alternative: totals only in `LEDGER_SYNC`, keeping the beacon to 48 bytes.
- [for gate] #4, P3 — `TASK_DONE` keeps `cpu_ns`. It is needed by M5-2's own text (a task's
  chunks are valued at "the median over workers" until the node has run one itself), but that
  median is a received value feeding a credit, which the Trust rule forbids. Alternatives:
  keep it for display only and change M5-2's fallback; or drop the field.
- [for gate] #5, P4 — the local link. Proposed: a Unix stream socket at
  `~/.local/state/paramesh/pmd.sock`, the same frames, 17 messages: register, admit request
  and its two replies, chunk report, segment counts, job end; quota, leave, abort, leave
  intent, new member; and for the tools, run request and its two replies, leave request and
  reply. `pmrun` starts the launcher as its own child so the program keeps the terminal.
  Alternative: tools reach `pmd` through the HTTP status API instead.
- [for gate] #7, P5 — copyset bits. Proposed: the launcher gives each member a `slot`, 0 to 63,
  in the `SEG_MAP` where it first appears, never reused in a job; copyset bit `slot` is that
  member. Alternative: rank of the node ID among current members, which changes when
  membership does and so would need every copyset rewritten.
- [for gate] #8, P6 — job ID. Proposed: generated by the launcher's `pmd`; high 16 bits its node
  ID, low 16 bits a counter kept on disk; 0 never used. Alternative: a random 32-bit number.
- [for gate] #9, P7 — discovery interface. Proposed: every IPv4 interface that is up, not
  loopback and multicast-capable, each peer recorded with the address first heard from;
  `pmd --iface <name>` restricts it. Alternatives: the default-route interface only (with a
  cable plus Wi-Fi that is usually the Wi-Fi); or `--iface` mandatory.
- [for gate] #10, P8 — fewer than N nodes accept. Proposed: run on those that accepted if the
  capacity check still passes, say so, and let M4-7's refill add nodes later; else refuse.
  Alternative: always refuse.
- [for gate] #11, P9 — the local `pmd` dies mid-job. Proposed: the job process treats it as
  fatal and the job ends with `PMD_LOST`. Alternative: keep running on the last quota and
  reconnect, buffering reports.
- [for gate] P10 — start sequence. Launcher first, admission in `pm_init()`, workers spawned
  after; `JOIN_JOB` is the first frame both ways on every connection; `SEG_MAP` at epoch 1,
  then `SEG_MAP_ACK` from everyone, then `pm_init()` returns. Differs from the HLD's step 2,
  as the person's G2 answer requires.
- [for gate] P11 — leave sequence. The HLD sends the new `SEG_MAP` after migration; the draft
  sends it before (the leaver and new homes need it), has a new home answer `BUSY_RETRY` until
  a segment arrives, and has the launcher answer `LEAVE_DONE` with `JOB_END` status `LEFT`
  once every remaining node has acknowledged the map. For M0-6 to carry through.
- [for gate] P12 — timers. The HLD puts every request under the 2 s reply timer. Proposed
  exemptions: `LOCK_ACQ`, `BARRIER_ENTER`, `SEG_MAP` and `L_ADMIT_REQ` at start-up, and
  `LEAVE_DONE`. Proposed meaning of `RETRY`: the receiver drops it, since TCP already delivered
  the request. Proposed new configuration key `job.start_timeout`, default 10 s.
- [for gate] P13 — `SEG_MAP` carries the home of every segment as a table. Alternative: members
  and weights only, each node computing the homes itself, as M1-6's Done-when ("identical on
  every node") suggests.
- [for gate] P14 — largest payload 1 MiB; `SEG_MIGRATE` sent in batches of at most 254 pages.
- [for gate] P15 — 17 status codes, and exit status 1 for a job process that ends abnormally.
- [for gate] P16 — Trust rule against admission. The capacity check sums `ram_commit` and
  `spill_commit` from other nodes and ranks peers by announced free capacity, yet the rule
  forbids a received value in "an admission decision". The draft reads the rule as covering
  the ledger and weights. Needs a ruling; the alternative is to reword the rule.
- [for gate] P17 — names of the environment variables (`PARAMESH_ROLE`, `_JOB_ID`, `_NODE_ID`,
  `_PMD_SOCKET`, `_LAUNCHER`, `_LISTEN`, `_PEERS`, `_CFG_<KEY>`). Only `PARAMESH_ROLE` is named
  in the HLD.
- [for gate] P18 — a worker reports its own fatal condition (a task threw, a second timeout, its
  `pmd` gone) by sending `JOB_END` to the launcher, which sends it to everyone.

**Done-when, part 1: every opcode in the HLD has a payload definition.** A scratch script
(`check_protocol.py`, in the session scratchpad) holds the HLD's 39 opcode names and reads the
document. Output:
`summary opcodes: 41; definitions: 58 (17 local); field tables: 50; HLD opcodes covered: 39/39;
gate tags: [1, ..., 18]` and `OK: no inconsistencies`. It checks that
- each of the 39 has a definition (its own section, or a row of the page-message table that
  names one of the two page payloads) and a row in the opcode table;
- no value is used twice, and the opcode table and the definitions agree;
- in all 50 field tables every offset equals the sum of the sizes before it, and the stated
  "Fixed size" or "Fixed part" equals the total;
- the sizes stated in prose hold: `HELLO` 300, `SEG_MAP` 2,212, `TASK_ASSIGN` 1,064, page frame
  4,140, `L_ADMIT_OK` 164, `L_SEGMENTS` 40, and 254 is the largest `SEG_MIGRATE` batch under
  1 MiB.

The script was then run on a copy with four planted errors (a wrong offset, a wrong fixed size,
a duplicated opcode value, a removed section): it reported all of them and exited 1.

**Done-when, part 2: byte order and alignment are stated.** Section 1: every multi-byte integer
is big-endian on every channel; there is no alignment and no padding, and decoders read byte by
byte.
