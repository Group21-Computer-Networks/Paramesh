### 2026-10-07 — session 2: engine, tests, demo

- `src/mem/uffd_engine.cpp` (352 lines): `mem_open` validates the size, maps the region at
  `kRegionBase` with `MAP_FIXED_NOREPLACE`, turns huge pages off, opens a user-mode-only
  userfaultfd, asks for the write-protect feature, registers the region for missing and
  write-protect faults, and starts the fault-handler thread (a pthread, so a failure to start
  is an error value, not an exception). The handler waits only on the userfaultfd and a stop
  eventfd and calls `FaultSink::on_fault`. `install` is `UFFDIO_COPY` (write-protected for a
  read-only page; `EEXIST` counts as success and wakes the page's waiters), `zap` is
  `MADV_DONTNEED`, `write_protect` is `UFFDIO_WRITEPROTECT`, `wake` is `UFFDIO_WAKE`. `read`
  goes through `process_vm_readv`, so a missing page gives `EFAULT` there instead of a fault
  that would park the calling thread. File descriptors and the mapping are held by small RAII
  classes; there is no `new` or `delete`.
- The destructor stops the handler thread, then unmaps the region, then closes the
  userfaultfd. In the other order a thread still parked on a fault is resumed on a fresh page
  of zeros, which the "never zero-fill" rule forbids.
- `src/mem/CMakeLists.txt`: finds and links `Threads::Threads`.
- `tests/unit/mem_test.cpp` (16 test cases). The first run of the first 15 passed, 109
  assertions; 200 repeats, 0 failures.
- `apps/m0_demo/`: the demo and its build file. A `LocalHome` object in the same process
  plays the remote node: it serves pages of a million-number array that nothing allocated,

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **`read` goes through the kernel** (`process_vm_readv`), not through the mapping. Reading a
  missing page through the mapping would raise a fault and park the network thread; this way
  it fails with `EFAULT`, which becomes `Errc::kState`, as the interface says.
- **`install` on an already mapped page wakes the page's waiters.** The copy that would have
  woken them did not happen, and the HLD counts `EEXIST` as success.
- **Teardown unmaps before closing the userfaultfd,** so a thread still parked fails its access
  instead of being resumed on zeros.
- **The handler thread is a pthread, not `std::thread`,** because the library is built without
  exceptions and a failed thread start must come back as an error.
- **Tests that map the region skip themselves** in a ThreadSanitizer build and where
  user-mode userfaultfd is missing, through doctest's `skip` decorator, and one test that
  always runs prints which of the three situations applies. The demo exits 77 where
  userfaultfd is missing, which `ctest` shows as skipped, and is not registered as a test in a
  TSan build.
- **The demo links `paramesh::mem` directly.** `AGENTS.md` says applications use `paramesh.h`
  only, but the library behind it does not exist before M1-7 and the card puts this demo in
  M0.
- **The demo checks sums, not fault counts.** The kernel may report a fault twice; the sums
  must be right regardless, and the counts are printed for the reader.
