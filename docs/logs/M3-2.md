### 2026-10-09 — session 2: queue, workers, wiring, tests

- `src/wire/`: payloads for `TASK_REQ`, `TASK_ASSIGN`, `NO_TASK` and `TASK_DONE`.
- `src/rt/tasks.h`, `src/rt/tasks.cpp`: class `Tasks`, and `rt_cut_range`.
  - Launcher: `parallel_for` checks the call, cuts the range, and queues the chunks; a
    `TASK_REQ` is answered with the next chunk or `NO_TASK`; the first `TASK_DONE` of a chunk
    lowers the count `pm_wait_all` waits on (the count built in M2-4).
  - Every process: worker threads. Each keeps one chunk to run and `task.prefetch` more asked
    for, runs them in order through `rt_run_task`, reports the CPU time, and after `NO_TASK`
    waits `task.no_task_backoff` (10 ms, doubling to 200 ms) before asking again. The
    launcher's own threads take from the queue directly and are woken when chunks arrive.
  - Chunks end on page boundaries of the array `pm_parallel_for_data` names, where its stride
    allows.
- `src/rt/sync.h`: the thread index moved here from `job.cpp` (`rt_thread_index`), since worker
  threads are now started in `src/rt/`; and `Sync::outstanding()` for `pm_finalize`.
- `src/lib/job.cpp`: starts the worker threads when the job is up and stops them in
  `pm_finalize`; routes the four opcodes; adds `pm_parallel_for`, `pm_parallel_for_data` and
  `pm_wait_all`. `pm_finalize` now refuses while work is outstanding, and `pm_malloc` from a
  task returns NULL, as `paramesh.h` says. The test hook shares `TASK_ASSIGN` and `TASK_DONE`
  with real tasks until M3-7 removes it, so its frames carry bit 63 in the chunk ID.
- Tests: `rt_test` (cutting, the launcher's queue by frames, worker threads against the fake
  transport), `wire_test` (the payloads), `lib_test` (three processes).
- One test of mine was wrong, not the code: the three-process test first relied on chunks
  taking long enough for every node's idle threads to wake, and failed once in 16 runs under
  UBSan with a node that ran nothing. The first chunks now wait until all three nodes have
  begun one, so the spread no longer depends on timing. 39 runs since, 0 failures.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **`Tasks` is a class owned by the job, like `Sync`;** `Runtime` and `rt_open()` stay
  unimplemented, as the person chose (Questions).
- **Thread count without `pmd`:** the program's `threads_per_node`, or one thread for each
  processor of the machine, and the default grain assumes every node has as many. M3-7 takes
  the quota from `pmd`. Marked `ponytail:` in `job.cpp`.
- **Default grain** is range / (4 x worker slots), as the Tunables table has it; with an
  array it is then rounded up to whole pages.
- **Page-aligned cuts** are made when the stride divides a page and the array is aligned to
  it, or the stride is a whole number of pages; otherwise the range is cut by the grain alone.
  A range or an array that starts inside a page gets a short first chunk up to the boundary.
- **Prefetch** means a thread has one more chunk asked for while it runs one. A chunk held
  this way is not given to another thread, as in the HLD.
- **Request numbers from the top quarter** (bits 63 and 62), apart from `Sync`'s and from the
  page requests of `src/lib/`. Marked `ponytail:`.
- **A frame that fits nothing ends the job** with status `PROTOCOL`: a chunk for a request
  nobody made, a `TASK_REQ` sent to a worker, a payload of the wrong size.
- **"From main()" cannot be told from another thread the program started itself:** both have
  no worker index. Calls from a task are refused; that is what the check can see.
- **Idle workers keep asking** every 200 ms for as long as the job lives; the plan's design.
