## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
Choices of form inside the card. Choices of meaning were asked (two answers) or are flagged.

- **The document holds the declarations in full, copied from the headers.** The gate freezes
  `INTERNAL_API.md`, not the headers, so the document has to be the exact contract; a script
  compares the two.
- **Callbacks are interfaces with `noexcept` members,** and every interface deletes copy and
  move, so an object held by reference elsewhere cannot be sliced or moved from under it.
- **`Result<T>` is a small class over `std::variant`,** because C++20 has no `std::expected` and
  the library is built without exceptions; `value()` and `error()` assert instead of throwing.
- **Each ID is its own struct with one field,** so the compiler rejects a page number passed as
  a node number; the unit test checks they do not convert.
- **`wire/frame.h` carries all 58 opcodes now,** though M1 implements a subset, so no later task
  has to edit the enum that every directory includes.
- **Factories are named `<dir>_open`** and return `std::unique_ptr`, so a directory's
  implementation class never appears in another directory.

- [answered 2026-10-07 by Amirishetty Sai Vignesh] The card says "header stubs in each `src/`
  directory", but nothing includes `lib`, `pmd` or `tools`: `lib`'s interface is `paramesh.h`
  and `pmd` talks to job processes through the local-link messages of `docs/PROTOCOL.md`.
  Stubs only where another directory calls in, or a header in all ten? Answer: "write it in a
  log and implement first option". So: headers for `platform`, `wire`, `coh`, `mem`, `store`,
  `net` and `rt`; none for `lib`, `pmd` and `tools`, and `docs/INTERNAL_API.md` says why.
- [for gate] I1 — one namespace `paramesh`, with free functions prefixed by their directory as
  in the HLD (`coh_step`, `home_step`, `mem_open`, ...). Alternative: a namespace per directory.
- [for gate] I2 — the HLD names four functions `mem_install()`, `mem_zap()`, `mem_wp()`,
  `mem_wake()`. The draft makes them members `install`, `zap`, `write_protect`, `wake` of an
  abstract `MemoryEngine`, adds `read`, and does the same for `HomeStore`, `LocalCache`,
  `Transport` and `Runtime`. Reason: `src/lib/` can then be tested in Actions against fakes,
  where the plan expects userfaultfd may be unavailable. Alternative: free functions with the
  HLD's exact names, and no fakes.
- [for gate] I3 — the HLD writes `home_step(entry, msg) → actions`. The draft takes the whole
  directory and appends actions to a vector; entry storage stays private to `src/coh/` and
  others see a `HomeEntryView`. Alternative: expose the entry struct, queue included.
- [for gate] I4 — `coh_step(state, current, event)` returns the new state, the new current
  request and at most four actions by value; the caller supplies an unused request number
  with each event.
- [for gate] I5 — `rt/runtime.h` includes `paramesh.h` (for `pm_task_fn`, `pm_lock_t`,
  `pm_barrier_t`), though the layout gives `rt` only `wire` and `net`. Alternative: `rt` keeps
  its own copies of those types and `src/lib/` converts.
- [for gate] I6 — home placement (the hashing of segments to homes) is in `src/store/`; M1-6's
  card lists `src/store/` and `src/rt/`. It returns the home of every segment as a table.
- [for gate] I7 — the transport handles `JOIN_JOB` and `HEARTBEAT` itself, fills in the header
  fields common to every frame, and provides one-shot timers for the back-off and the hold
  window.
- [for gate] I8 — payload structs are not in this draft. M1-1 adds one per opcode it
  implements, named `<Message>Payload`, with `wire_encode` and `wire_decode_<message>`; they
  join the frozen interface when they exist, which needs the person's approval then.
- [for gate] I9 — the nine `Errc` codes.
- [for gate] I10 — Still open #12 (affinity by "cached at") is a gate point this interface
  touches: the runtime can ask only for a page's home (`RuntimeHost::home_of`), which is all
  M3-3 needs as worded. Affinity by cache would need new information from other homes, here
  and in `docs/PROTOCOL.md`. #14 and #15 are also gate points; nothing here depends on them.
