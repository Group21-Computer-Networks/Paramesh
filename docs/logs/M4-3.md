### 2026-10-13 — session 2: the store, the wiring, the job test

- `src/store/home_store.cpp` (was `ram_store.cpp`): one store. Pages in RAM up to the cap;
  when RAM is full CLOCK picks the first page not used since the hand last passed, and a
  thread of the store's own writes it to the spill file and says `on_spilled`. `load()` has
  that thread read a page back and say `on_loaded`; when RAM is full a cold page takes the
  loaded page's place in the file, so neither the cap nor the budget is passed on the way.
  The mutex is never held across a read or write of the file.
  - A page being written out still counts as RAM. `put()` of a new page then answers
    `Errc::kState` and the caller puts again after `on_spilled` (3A). After a `put()` that
    fills RAM the store spills one page ahead, so the next page usually finds room.
  - `Errc::kNoSpace` only when RAM and the spill budget are both used up.
  - The file is made with `mkostemp()` in `StoreConfig::spill_dir` and unlinked at once: it
    goes when the process does, however it ends.
  - A failed write loses nothing (the page stays in RAM) and ends spilling; a failed read
    marks the page lost and `get()` reports the error, so the job ends. No zeros, no stale
    copy.
- `src/store/home_store.h`, `docs/INTERNAL_API.md`: `StoreConfig::spill_dir`; `put()`'s
  `Errc::kState`.
- `src/lib/job.cpp`:
  - the store gets its RAM share, `spill.budget` (`PARAMESH_CFG_SPILL_BUDGET`, bytes; the RAM
    cap if unset; none without a cap) and the directory of `pmd`'s socket;
  - the store's `on_spilled` and `on_loaded`, which may come on its thread, are queued and
    applied on the network thread: a spilled page's directory entry becomes `SPILL`; a loaded
    page is the `LOADED` event if its entry waits in `W_LOAD`;
  - the home machine's load action calls `store.load()`;
  - when the store answers `kState` to a put, or `kSpilled` to a get the directory took for
    RAM (the store moves pages on its own thread, so the directory can be a moment behind),
    the action and those after it wait, with every later home event behind them, and go on at
    the store's next word. The page is asked for in the second case.
  - The home action loop is split into small functions for this; no message changed.
- Tests: three store cases (store_test) and the job test (pmd_test); results under
  Verification.
- clang-tidy: three findings on the first run (the action loop's complexity, a nested
  conditional and an increment inside a condition in the new test code); fixed, exit 0.
- State: Done-when met.
### 2026-10-14 — session (fix): a store test that raced the I/O thread

- The CI job `gcc / thread` on PR #48 failed twice in "a full store spills the cold page,
  says so, and reads it back on load": `store_test.cpp:159`, `CHECK( 4096 == 8192 )`.
  Reproduced locally under TSan pinned to one CPU (`setarch -R taskset -c 0`): 249 runs of
  300 failed.
- Cause, in the test: `put(3)` is told to wait (`kState`) and in the same call asks the I/O
  thread for room. The next check expected RAM still to hold two pages, but on a slow
  machine the I/O thread had already spilled one. The store was right; the check depended
  on timing. Traced by printing every change of the RAM count (removed again).
- Fix, test only, as the person chose ("pause the writer", 2026-10-14): `Told` can hold the
  store's I/O thread in its next `on_loaded` (at most 10 s) until let go. The test holds it
  from the read-back of page 1 until after the `kState` check, so every exact check stays
  as it was. No library change.
- Commands: the same loop, `unit_store_test`, TSan, one CPU: 0 of 300 failed; 50 runs each
  in the GCC no-sanitizer and address builds and the Clang thread and undefined builds: 0
  failed. `cmake --build --preset tidy`: exit 0. clang-format: clean.

### 2026-10-22 — session (fix): put() refused a page while the last spill was being written

- Found while verifying X-prefetch: under heavy load, "a job whose region is twice the RAM
  caps" (pmd_test) aborted with "the home store is full", 7 of 35 runs with prefetching on and
  0 of 24 with it off. The launcher's stderr goes to /dev/null in that test; routed to a file
  for the hunt, its store said at the refusal: RAM 1,536 of 1,536 pages, spill slots 2,560 of
  2,560, 4,095 pages kept, so one place more in use than pages kept.
- Cause, in the store: after a put() that fills RAM, the I/O thread spills a cold page ahead.
  While it writes, the page is in RAM and holds its slot both, as the header says ("kState
  while a page is being written to make room"). But put() looked at the file first: if that
  write had taken the last slot, a new page was refused with kNoSpace although the write was
  about to free a place in RAM. A node's spill budget is now sized to what it keeps
  (X-node-commit), so the last page of a node always meets the last spill; it lost the race
  only if it came while that write was going on, which prefetching made common.
- Fix: `spilling_`, set while make_room() writes; put() answers kNoSpace only when RAM and the
  file are used up and no such write is going on, else kState and the caller puts again on
  on_spilled, as for any spill.
- Test (`store_test.cpp`): a store of one RAM page and one spill page takes page 1 (spilled
  ahead into the one slot), then page 2 is put again and again until taken; every answer must
  be kState or success, 300 rounds. Without the fix: failed 3 of 3 runs (`REQUIRE( 3 == 1 )`,
  kNoSpace). With it: 5 of 5 pass, the store's 11 cases; 3 of 3 under TSan and 3 of 3 under
  ASan. `cmake --build --preset tidy`: clean. clang-format: clean.
- Two other failures of that pmd_test case seen in the same loaded runs are not this and not
  prefetching: the job refused at admission (pmrun saw one node: the daemons had not listed
  each other yet), and `pm_init` returning after the 10 s start timeout with the network thread
  running, so the program's return ends in std::terminate. In docs/TODO.md with X-prefetch.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **One store, not two:** the RAM-only store of M1 is the same code with no spill file
  (`load()` still answers `kUnsupported` then, as its M1 test expects).
- **Spill ahead by one page:** a put that fills RAM starts one write, so that the usual put
  does not have to wait.
- **A loaded page gives its slot back;** the file holds only pages that are not in RAM.
- **The directory may be a moment behind the store, either way,** and both are handled: a
  get that finds the page in the file asks for it and waits; a load of a page already in RAM
  is answered at once.
- **One waiting action holds back every home event of the node** for the one disk operation
  (marked `ponytail:` in the code); a queue for each page if a measurement shows it.
- **`spill.budget` is given in bytes.** Its default is the RAM cap the process got.
- **The two pages the I/O thread reads into and writes from are outside the cap:** 8 KB,
  fixed.
