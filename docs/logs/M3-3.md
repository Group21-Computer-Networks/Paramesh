### 2026-10-09 — session 2: the choice, the count, the comparison

- `src/rt/tasks.cpp`: each queued chunk records the home of its first page, from
  `RuntimeHost::home_of` (the launcher's own segment map); a call with no array has none.
  When a node asks, the queue gives it the first chunk homed on that node, or else the first
  chunk. `TasksConfig::affinity` turns this off, and the queue is then first in, first out.
- `src/lib/job.cpp`:
  - counts the pages, or rights to pages, that reach this process from other nodes
    (`READ_DATA`, `WRITE_GRANT`, `UPGRADE_GRANT`, `FETCH_DATA`), and logs the count when the
    job ends in order: event `job_pages`, field `received`, level info;
  - reads `PARAMESH_CFG_LOG_LEVEL` (the plan's `log.level`) and `PARAMESH_CFG_TASK_AFFINITY`.
- Tests: `rt_test` drives the queue by frames; `lib_test` runs the same job twice on three

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **A chunk's home is the home of its first page.** A chunk of several pages can span two
  homes at a segment boundary; one page is enough to choose by.
- **Home only, not "cached at":** as the card says and as the M0 gate confirmed (Still open
  #12): the launcher reads its own segment map and asks no other node.
- **What is counted as a page transfer:** a `READ_DATA`, `WRITE_GRANT`, `UPGRADE_GRANT` or
  `FETCH_DATA` that arrives from another node. A grant of a page never written carries no
  bytes but still costs a round trip, so it counts. Frames a node sends itself do not.
- **A switch that is not in the plan's Tunables table:** `PARAMESH_CFG_TASK_AFFINITY=0`. The
  card's check compares a run with affinity on and one with it off, so something must turn
  it off. On is the default. In `docs/TODO.md` for the person to accept or drop as a key.
- **The log level stays `warn` unless `PARAMESH_CFG_LOG_LEVEL` says otherwise.** The plan's
  default is `info`; with it every job would write lines to stderr, which the earlier tests
  read. M3-7, where settings come from `pmd`, is the place to change the default. In
  `docs/TODO.md`.
- **The scan of the queue is linear.** Marked `ponytail:`.

Local, 2026-10-09.

**Done-when: with affinity on, fewer page transfers are logged for the same run than with it
off.** `unit_lib_test`, "with data affinity on, fewer page transfers are logged for the same
run". The job: three processes, two threads each; one array over six segments, filled by 96
chunks of 32 pages; each chunk writes one number in every page. It is run twice, and the
`received` counts the three processes log are added up.

| Build | Runs | With affinity | Without |
| --- | --- | --- | --- |
| dev | 9 | 583 to 757 | 2,081 to 2,207 |
| gcc ASan | 4 | 584 to 588 | 2,012 to 2,078 |
| clang UBSan | 4 | 593 to 666 | 2,140 to 2,208 |

About 3.4 times fewer. What remains with affinity on is mostly the chunks a node takes from
another when it has none of its own left, and the launcher's reading back of one page of
each chunk.

`unit_rt_test`, "a node that asks is given a chunk whose data it is home for, else the first
chunk": six chunks homed two each on nodes 1, 2 and 3; nodes 3, 2, 3, 3, 2, 2 ask and get
chunks 5, 3, 6, 1, 4, 2. With affinity off, and for a call with no array, they get 1 to 6 in
order.

Quality gate: all eight compiler and sanitizer builds pass, 15/15 tests (14/14 under TSan), no
warnings; clang-tidy exit 0; clang-format clean.
