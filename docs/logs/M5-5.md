### 2026-10-17 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
- Asked the person three things (answers below): nothing measured fault latency, so a small
  bench app (`apps/faultlat`, outside the card) was approved; the free-rider is a node that
  never runs anyone else's work; the free-rider experiment sets `ledger.scale` small.
- `apps/faultlat` (new): the launcher writes N pages; tasks, handed out without data affinity,
  read the first byte of each page, timing each read (the first touch faults and fetches the
  page from the launcher). Chunks that land on the launcher's node sleep 5 ms instead, so the
  others get the reads (without that its threads read every page, locally, and nothing was
  timed). Prints count, p50, p90, p99 and max in microseconds.
- `tools/bench/fairness.sh` (new): daemons on this machine with their own ports and seeds.
  `jain`: three nodes start a matrix multiply at once; Jain's index over 1/time. `freerider`:
  a fourth node gives the contributors a discovery port nobody listens on, so they never hear
  it and never ask it for a worker, while it asks them; each round all four start a job at
  once; prints the free-rider's weight at node 1 (/v1/ledger) and its share of the round's
  throughput. `latency`: faultlat alone, then beside two matrix multiplies.
- First free-rider run: its weight hardly moved (0.99 to 0.97). Each node's own job asked for
  every core and own jobs come first, so guests only had the slots the waiting rule gives and
  weights decided nothing. Jobs now ask for one thread a node (`-t 1`) with `--cap-cores 2`:
  the node's own job leaves one slot, which the guests share by weight.
- Commands and results: see Verification.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Share is measured as throughput,** 1 / job time, of the jobs started together; pmd does
  not publish each job's slots.
- **The free-rider's share** is its throughput over the round's total, with its weight at
  node 1 beside it.
- **Jobs ask for one thread a node by default,** so that weights, not "own jobs first",
  decide the guests' slots (above).
- **No unit test:** the deliverables are a bench program and a script, and the script's run
  is their check.
