### 2026-10-16 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
  Still open #13 and #14 were settled at the M0 gate: the unit of work is the number of
  indexes, and work taken from me is my own measured CPU time on the peer's chunks.
- Asked the person: the card values a peer's chunk at my own cost "(the median over workers
  until I have run one myself)", but `L_CHUNK` carries CPU time only for this node's own
  chunks, so `pmd` never sees workers' times. Answer: until this node has run the task
  itself, that credit waits, counted in indexes, and is valued once it has.
- `src/pmd/ledger.{h,cpp}`: the ledger keeps this node's own chunks of every task, any job
  (`own`, saved with the rest; a ledger without it, from M5-1, still reads). `apply_credits()`
  works out every credit again from the raw counts, in core-seconds: given = each index a
  peer ran x this node's CPU seconds per index of that task, plus segment-seconds x 2 MB in
  GB-hours x the rate; taken = this node's own measured CPU seconds on the peer's chunks, plus
  its segment-seconds for the peer the same way. `pending_indexes()` counts what waits for a
  measure. `balance()` (M5-1) is given minus taken.
- `pmd`: a job process's report of its own chunk is also a measure for `own`; the rate comes
  from `PARAMESH_CFG_LEDGER_MEM_RATE` (`ledger.mem_rate`, default 450 core-seconds per
  GB-hour); credits are worked out before each save.
- Tests (`tests/unit/pmd_test.cpp`): "credit rules: fixed counts give the expected balances,
  from this node's measures only": balance 223 core-seconds from hand-worked counts; a
  different claimed CPU time from the peer changes nothing; a task never run here leaves 700
  indexes pending until this node runs it, then 3.5; twice the rate gives twice the memory
  credit; the measures survive a save. The three-daemon test from M5-1 also checks that both
  sides end with credits.
- Commands: the three cases: passed. `ctest --test-dir build/dev`: 16 of 16. clang-tidy: one
  finding (`auto`), fixed, exit 0. clang-format: clean.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **This node's cost of a task is its total CPU time over its total indexes,** over every
  chunk of the task its own threads ran, in any job; the ledger keeps totals, not each chunk.
- **Credits are worked out again from the raw counts each time** (before each save, at most
  once a second), not added up as chunks arrive, so a later measure values pending work and a
  change of rate applies to all of it.
- **Credits are in core-seconds; 2 MB is `kSegmentSize` and a GB is 2^30 bytes.**
- **`pmd.cpp` is touched for three lines** (own measures, the rate, the call before a save):
  the card's "ledger files" are what it changes; the daemon only feeds them.
