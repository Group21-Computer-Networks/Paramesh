## Decisions

<!--

- **h(segment, node) is the SplitMix64 finaliser.** The HLD gives the formula but not the hash;
  this one is a few lines, well mixed, and has no dependency.
- **Scores are computed in `double`.** Every node of a job runs the same binary on the same
  architecture, so they agree; and `SEG_MAP` carries the table the launcher computed, so a
  difference could not split the job anyway.
- **The allocator is a private header of `src/rt/`,** not part of the frozen interface: only
  the runtime calls it.

Local, 2026-10-07, over all 2,048 segments of a full region and three nodes weighted 2:4:2.

- **Hashing is identical on every node for the same inputs:** the placement is the same for
  the members in three different orders and when computed again.
- **Removing one node moves only that node's segments:** with the middle node removed, every
  segment it was home for has a new home and every other segment keeps its home.
- Also: the node with twice the RAM is home for between 900 and 1,150 of the 2,048 segments; a
  member with weight 0 hosts none and changes nothing; no member with RAM is an error.
- Store: put, replace, get, drop, the RAM cap, `load` unsupported. Allocator: 16-byte and page
  alignment, a large allocation owning its pages, zero bytes, a full region, no overflow.
