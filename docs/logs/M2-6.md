### 2026-10-09 — session 2: the harness, 100,000 schedules, and planted bugs

- `tests/sim/fuzz.cpp`:
  - Moves: any node may read, write, add atomically or evict any page at any step. In M1
    only one fixed node wrote each page, and readers waited for it.
  - Messages: all 15 of the page and atomic groups are delivered and carried out, including
    `WRITEBACK` after an eviction.
  - Checks after every step: the six invariants of `docs/STATE_MACHINES.md` section 4. New
    are "no early discard", "zeros only for unwritten pages", an atomic add applied to an
    old copy, and a store of bytes the home did not receive in that step.
  - At the end of a schedule nothing may still wait: no node, no atomic add, no home entry.
  - `--schedules` prints how often each message was delivered, so a path nobody reaches shows.
- The machines needed no change: every schedule passed from the first run.
- Planted five bugs in `src/coh/`, one at a time, to see the harness catch each (table under
  Verification); `src/coh/` is unchanged on this branch.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Eviction and atomic adds are fuzzed too,** although nothing raises them in a job before
  M4 and M2-5: both machines have their rows since M2-1 and M2-2, and "no early discard" is
  about eviction.
- **Not fuzzed:** the hold window (AT-1), the load of a spilled page and migration with
  `BUSY_RETRY` and `REDIRECT` (M4). The harness never moves a home copy to the spill file and
  the home never sends those two replies.
- **"No lost update" follows the document's list exactly:** a read copy does not count as
  holding the bytes; a node in `M` or `M→I`, a node in `S→M` once the home records it as
  owner, the home copy, or a `WRITE_GRANT`, `FETCH_DATA` or `WRITEBACK` in transit do.
- **One home (node 1) for all three pages,** as in M1. The protocol is per page, and node 1 is
  also a reader and a writer, so the home's own requests are covered.
- **The ctest entry stays at 2,000 schedules** (`fuzz.schedules` in Actions); 100,000 is run by
  hand, here and at the M2 gate.

2,000 schedules are the ctest entry `sim.fuzz`, which Actions runs in all eight builds; here it
takes 2.4 s plain and 11 s at most (gcc TSan). `sim.fuzz_self_test` passes: the planted bug is
caught at seed 1, fails identically again, and the seed passes without it.

**The harness catches what it is for.** Each bug was planted alone in `src/coh/` and removed:

| Planted bug | First failure in 2,000 schedules |
| --- | --- |
| An atomic add does not invalidate the requester's read copy | seed 1: "stale read: node 3 holds an old copy of page 0" |
| A page being evicted is discarded on `FETCH` | seed 5: "early discard: node 3 dropped page 0 before the home had it" |
| The home grants a write after the first `INV_ACK` | seed 1: "the home aborted on page 1" (the second acknowledgement is impossible) |
| `FETCH_INV` leaves the page mapped | seed 1: "node 3's state and its mapping or request disagree" |
| A late `WRITEBACK` is stored | seed 1: "the home was to store bytes it does not have" |

Quality gate: all eight compiler and sanitizer builds pass, 15/15 tests (14/14 under TSan), no
warnings; clang-tidy exit 0; clang-format clean.
