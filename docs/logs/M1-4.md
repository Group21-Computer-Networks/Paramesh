### 2026-10-07 — session 2: built and checked

- `src/coh/home_machine.cpp`: `home_open`, `home_add_segment`, `home_entry` and `home_step` for
  the 8 rows the document marks M1 (listed from the document with a script). A request for a
  busy page is queued and served in arrival order when the page is free.
- Anything else produces one `kAbort` action. The frozen `HomeAction` has no status field, so
  the action's `opcode` says which kind: the refused request's opcode for "not supported
  before M2", `kHeartbeat` for an impossible pair. M1-7 turns the first into status
  `UNSUPPORTED` and the second into `INTERNAL`.
- Not implemented, because nothing in M1 calls them: `home_remove_segment`,

  (M4-3), `home_drop_member` (M4-5). They remain declared.
- `tests/unit/coh_home_test.cpp`: 7 cases, 96 assertions, passed on the first run.
- First version used `new` and `delete` for the opaque directory; replaced with

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Entries live in a hash map keyed by page, created on first use,** each with its own queue.
  Marked `ponytail:` with the upgrade (a flat array per segment) if a million pages make it
  too heavy.
- **The abort action's `opcode` distinguishes "not supported" from "impossible"** (above),
  which avoids changing a frozen struct for something M2 removes.
- **`FETCH` carries no request number from the machine:** the caller assigns one when it sends,
  and the answer is matched by page and sender.
