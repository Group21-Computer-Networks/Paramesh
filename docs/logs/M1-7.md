- A point the plan leaves to this task: M1 has no locks or barriers, and its home refuses a
  write to a page others hold, so a worker must not read before the launcher has written. The
  plan's "test-only hook, outside the public header" therefore has to carry a "go" from the
  launcher. Plan: `pm_test_run_on_workers(id)`, sent as `TASK_ASSIGN` and answered with
  `TASK_DONE`, in a private header of `src/lib/`.
- Next: `src/lib/job.cpp`, the hook header, and a three-process test.

### 2026-10-08 — session 2: built and checked

- `src/lib/job.cpp` (879 lines): one `Job` object per process, which is the transport's
  handler, the memory engine's fault sink and the store's event sink.
  - `pm_init`: reads `PARAMESH_ROLE`, `_JOB_ID`, `_NODE_ID`, `_LISTEN`, `_PEERS`; hashes
    `/proc/self/exe`; opens the platform, the memory engine (always the full 4 GiB mapping),
    the home directory, the store and the transport; adds every peer. A `JOIN_JOB` with a
    different hash ends the job with `BINARY_MISMATCH`.
  - Launcher: when every worker has joined, places the segments (equal weights), applies the
    map, sends `SEG_MAP` at epoch 1, and returns from `pm_init` when every `SEG_MAP_ACK` is in,
    or `PM_ERR_NETWORK` after `job.start_timeout` (10 s; `PARAMESH_CFG_JOB_START_TIMEOUT`).
  - Worker: acknowledges the map once it has joined every member, then serves until `JOB_END`.
  - Faults go from the handler thread to the network thread through a queue and a zero-delay
    timer; all protocol state is touched on the network thread only. Actions from `coh_step`
    and `home_step` are carried out against the memory engine, the store and the transport.
    A frame a process addresses to itself is queued and handled in the same loop.
  - `pm_malloc` uses the M1-6 allocator; `pm_finalize` sends `JOB_END` (OK) and waits up to
    2 s for the workers to close; `pm_strerror` is filled in.
  - Abort: a lost peer, a reply timeout, a malformed frame, or an abort action. The launcher
    sends `JOB_END` to everyone; a worker reports to the launcher, which passes it on; each
    process prints `job <id> aborted: <message>` and exits 1.
- `src/lib/test_hook.h`: `pm_test_register`, `pm_test_run_on_workers`, `pm_test_fail`. The "go"
  travels as `TASK_ASSIGN` with the function's number as chunk ID and is answered by
  `TASK_DONE`, in the protocol's layouts.
- `tests/unit/lib_test.cpp`: 3 cases. Passed on the first run (2.8 s).
- clang-tidy, first run: a `FILE*` (now an `ifstream`), six `getenv` calls (now behind one
  helper, read before any thread starts), a nested conditional, unchecked `fprintf`/`fflush`,
  16 `return f();` in void functions, and smaller ones in the test. All fixed; then exit 0.
- Repeats of the three-process test: 15 without a sanitizer, 5 under clang ASan, 5 under gcc
  UBSan: 0 failures, no process left behind.
- Nothing in `src/mem/` needed changing.
- State: Done-when met.

### 2026-10-28 — session (fix): a start timeout that said nothing, after a start-up that was slow

- CI run 40572367809, job 122429663496 (clang, no sanitizer, PR #81, which changed only shell
  scripts) failed `unit.lib_test` in "with prefetching on, workers reading in order read the same
  numbers, waiting less". The whole log of the three processes was one line,
  `job 42 aborted: node 2 lost`; `ok` and `workers == 2` failed. That runner was slow:
  `unit.lib_test` took 130.55 s there, against 75.76 s for the same tests on `main` (run
  40572206800).
- Reproduced locally with ASan, 4 runs side by side pinned to 2 cores (`taskset -c 0,1`): 1
  failure in 16, in the prefetch-off half of the test. It also failed with plain clang, 6 runs
  side by side on 2 cores: 1 in 24. `PARAMESH_CFG_PAGE_ENCODING=on`, 4 side by side: 16/16
  passed. I added code (later removed) to print the exit statuses: every failure was `2 2 2` or
  `2 2 1` (launcher, node 2, node 3). Status 2 means `pm_init` returned an error to the test
  program, which then returns 2 and prints nothing. Only a peer that had joined says
  "node N lost". No ASan report was printed.
- Cause: `Job::start()` waits `job.start_timeout` (10 s) for the job to come up, counted from the
  end of this process's own set-up. A peer cannot be joined until it has finished its own
  set-up and listens. So a process whose set-up lags the others' by more than 10 s makes every
  process give up, with no message. I confirmed this by adding a sleep (later removed) after the
  hash in one node: 5 s and 9 s pass, and 11 s fails exactly as in CI, for node 1, 2 or 3. The
  start handshake itself never stalled.
- Most of set-up was `hash_binary`. It read `/proc/self/exe` one byte at a time through
  `std::istreambuf_iterator`, then ran SHA-256. For the 18.9 MB clang debug `unit_lib_test`
  that took 2.2 s of CPU per process: about 1.2 s reading and 0.96 s hashing (`sha256sum` of
  the same file: 0.019 s). Under ASan it was 4.8 s. Each test job starts three such processes at
  once, which gives an uneven or overloaded runner room to push one far behind the others.
  Prefetching and page encoding play no part: they run only after the job is up.
- Fix in `src/lib/job.cpp`:
  - `hash_binary` reads the file in one `read`.
  - A start timeout now logs `start_timeout` (error level, through the logger) with
    `not_joined`, the members this process never heard from, and `seconds`. This follows the
    card's rule that a timeout ends with a message.
  - `joined_` is now written under `mutex_`, which `start()` holds when it reads it.
- Effect: "three processes on localhost complete the M1 program" takes 1.70 s instead of 2.70 s
  (clang debug) and 3.01 s instead of 6.21 s (ASan).
- New test "nodes that never start: pm_init fails after the start timeout and names them". Only
  one process starts, the launcher and then a worker, with `PARAMESH_CFG_JOB_START_TIMEOUT=1`.
  Its `pm_init` must return `PM_ERR_NETWORK`, and the log must name the two missing nodes.
  Without the fix it fails: both `start_timeout` checks, `0 > 0`. With it: 20/20 passed.
  - A first version started two of the three nodes. It failed 8 of 20, because the first
    process to give up exits and the other then sees "node 1 lost" before its own timer fires.
    That race is real, so the test was changed to avoid it rather than weakened, and the race
    went to TODO.md.
- Deferred to TODO.md:
  - The launcher does not end the job with `START_TIMEOUT` as PROTOCOL.md section 11 proposes.
  - PicoSHA2 at -O0 still costs about 1 s per process, in `src/platform/`, outside this card.
- Verification of the fix, local, 2026-10-29 (16 cores; the machine restarted twice when I ran
  the earlier 48-process stress batches, so the later runs were smaller):
  - clang-format: clean.
  - `tidy` preset: first run, 3 findings in the new test (`getenv` results not checked, and
    `atoi`); fixed; then exit 0.
  - `ctest` with the `dev`, `asan` and `ubsan` presets: 16/16 pass each. With `tsan`: 15/15
    pass (the region tests skip themselves).
  - The new test: 10/10 pass (dev build), after the tidy fixes.
  - The CI case under ASan, 4 runs side by side pinned to 2 cores, 16 runs: 0 failures (1 in 16
    before the fix). The failure was rare, so this shows the fix does no harm. It does not
    prove the flake is gone.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **The hook carries a "go" from the launcher** (`pm_test_run_on_workers`), not just "a function
  chosen by role". Without locks or barriers a worker cannot know the launcher has finished
  writing, and in M1 a read that comes first makes the later write a refused request.
- **Every process maps the full 4 GiB;** the job's region size only limits the segment map and
  the allocator. A worker maps before it knows the size, and an unreserved mapping costs nothing.
- **A fault reaches the network thread through a zero-delay timer** of the transport, the one
  frozen way to run something on that thread.
- **An abort exits after a 150 ms linger,** so the `JOB_END` leaves first. Marked in the code as
  a constant; flushing the transport explicitly would need a new interface call.
- **Not implemented, because M1 does not use them:** the other `paramesh.h` functions (they stay
  undefined until their tasks), `pm_register_task` (M3-1), log lines beyond warnings.
- **The three-process test skips itself under ThreadSanitizer,** which cannot map the region.
  So the threading of `job.cpp` is checked by ASan and UBSan runs and by design, not by TSan.

Local, 2026-10-08 (kernel 7.0.0-38, loopback).

**Done-when: three processes on localhost complete the M1 test program.** `unit.lib_test` forks
node 1 as launcher and nodes 2 and 3 as workers, each configured only by environment
variables. The launcher allocates 6 MiB of 64-bit numbers (three segments, so homes on more
than one node), writes them, has both workers read and check every one, reads them back
itself, and ends the job. All three exit 0 and the launcher prints nothing.

**A lost node makes every process exit with a message.** Same job, but node 3 kills itself
half way through reading: the launcher and node 2 both exit 1, and the launcher's stderr is
exactly `job 42 aborted: node 3 lost`.

Also: `pm_init` without the environment returns `PM_ERR_CONFIG`.
