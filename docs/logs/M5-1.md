### 2026-10-15 — session 1

- Started the task. Read the card, the milestone's Streams and Gate text, and AGENTS.md.
  The reports are docs/PROTOCOL.md's `L_CHUNK` (one finished chunk) and `L_SEGMENTS` (the
  segment homes at each epoch), section 9.
- Asked the person: the card lists `src/pmd/` and `tests/unit/`, but the reports need their
  codecs in `src/wire/` and the sending side in `src/lib/job.cpp`. Approved (below).
- `src/wire/`: `L_CHUNK` and `L_SEGMENTS`, with a wire test.
- `src/pmd/ledger.{h,cpp}` (new): per peer and per job, in both directions (`for_peer`, this
  node's work for the peer's job; `by_peer`, the peer's work for this node's job), chunks,
  indexes and CPU time per task, segment-seconds, and a credit for M5-2 to set. `balance()`
  is credits given minus taken, behind `LedgerView`, the interface M5-3 will fake. Saved as
  JSON by writing `ledger.json.tmp`, `fsync`, `rename` over `ledger.json`, and `fsync` of the
  directory; a file that is not a ledger stops `pmd` from starting rather than being lost.
- `pmd`: reads the ledger in `open()`. A worker's own chunk is recorded as `for_peer` of the
  job's launcher; a launcher's report of a peer's chunk as `by_peer` of that peer; a node's
  own work on its own job is not recorded. `L_SEGMENTS` counts become segment-seconds from
  pmd's own clock, until the next epoch or the process's end. Saved when changed, at most once
  a second, and as `pmd` stops.
- Job process: `chunk_finished` and every new map queue an `L_CHUNK` or `L_SEGMENTS`; one
  writer thread sends them, so the network thread never waits on the socket. The queue is
  sent before a worker exits on `JOB_END` and before the launcher closes its link to `pmd`.
- Found by the daemon test below: workers never reported their own chunks. `src/rt/runtime.h`
  says every process calls `chunk_finished` for chunks its own threads ran, but
  `src/rt/tasks.cpp` called it only on the launcher. Asked; approved to fix it here: a worker
  thread now calls it after each chunk with the CPU time it measured, and the launcher passes
  0 for a peer's chunk, as runtime.h says. Two `rt_test` cases check both.
- Tests (`tests/unit/pmd_test.cpp`): the ledger's round trip, balance and refusal of files
  that are not ledgers; a process SIGKILLed in the middle of saving (as soon as the temporary
  file appears) leaves a ledger equal to the old or the new one, never anything else, 20
  rounds; and three daemons after a job: the launcher's `by_peer` indexes equal each worker's
  `for_peer` indexes, workers measured CPU time, both sides have segment-seconds, and a daemon
  started again on node 2's state directory reads the same ledger and leaves it unchanged.
- My mistake on the way: the kill test first slept a fixed 2 to 22 ms before killing, but a
  save takes about 150 ms in the debug build, almost all of it making the JSON, so no kill
  landed during a write (0 of 40). It now waits for the temporary file, so every kill lands
  in the write (20 of 20).
- Commands: the three ledger cases, three runs: passed. `ctest --test-dir build/dev`: 16 of
  16. `cmake --build --preset tidy`: exit 0. clang-format: clean.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **A node's own work on its own job is not in the ledger:** it involves no peer.
- **Segment-seconds are kept as a real number of seconds,** from pmd's own clock; `HELLO`'s
  totals (M5-4) round them.
- **The ledger is saved at most once a second while it changes, and when pmd stops.** The
  second is a constant beside the beacon interval, not a tunable: the plan's table has none
  for it, and a crash loses at most one second of counts.
- **A file that is not a ledger stops pmd** (`open()` fails) rather than being replaced by
  an empty one, so a damaged ledger is never silently lost.
- **`LedgerView::balance()` is the interface M5-3 fakes;** M5-2 sets the credits it sums.
