### 2026-10-08 — session 2: built and run

- `apps/readshare/main.c` (C11) and its build file. The launcher takes three 2 MiB arrays
  (three segments), writes `numbers` values at the start of each (default 8,192), has every
  worker check them through the test hook, and reads them back. It links the C++ library
  from a C program without change.
- `tests/multi/run_local.sh`: picks a free port per node, starts N processes with the
  environment of `docs/PROTOCOL.md` section 10, waits (default 60 s), prints each node's exit
  status and output, then `PASS` or `FAIL`. Exit 0, 1, or 2 for bad usage.
- `tests/multi/run_netns.sh`: re-runs itself inside `unshare --user --map-root-user --net
  --mount` (or through passwordless sudo), makes a bridge, and per node a network namespace
  with a veth cable, the address 10.77.0.i and `tc ... netem delay D ms loss L%` on its link.
  It then calls `run_local.sh` with the addresses and the namespaces, so starting, waiting
  and reporting exist once. No root was needed on this laptop.
- `apps/.clang-tidy`: applications inherit the root checks minus six that reject normal C
  (macros for constants, a file-scope variable, `printf`, an unchecked `printf` result) and
  the int-to-pointer check; each with its reason in the file.
- Runs are under Verification. One fix along the way: bash printed "Killed" for each process
  the timeout path killed; the cleanup now waits for them quietly.
- State: Done-when met. All nine M1 tasks are done.

## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **`run_netns.sh` sets up the network and hands over to `run_local.sh`,** so the two scripts
  share the start, wait and report code without a third file.
- **Namespaces without `ip netns`:** each node's namespace belongs to a sleeping holder process
  and is entered with `nsenter`. `ip netns add` needs a writable `/run/netns`, which an
  ordinary user does not have.
- **`netem` is on each node's own link,** so `-d 5` adds 5 ms to every packet a node sends: 10 ms
  to a round trip.
- **The program writes little by default** (three arrays, 16 pages each) so a run with 25 ms of
  delay takes seconds; its argument raises that.
- **The program finds the arrays at the region's base address.** Until tasks carry arguments
  (M3) there is no other way to tell a worker where the launcher's data is.
- **Not run in Actions.** The plan keeps multi-node tests to local scripts; the program is
  built there with everything else.
