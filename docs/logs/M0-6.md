  - First run failed after 5 steps: "lost update: nobody holds version 0". The tables were

    still in `S→M` while `UPGRADE_GRANT` travels. Corrected the check and the document's

  - Controls: with the HLD's home rule 5 (UNCACHED after `WRITEBACK`) the model reports "home

## Questions and blockers

<!--
Each item starts with [open] or [answered YYYY-MM-DD by <who>], followed by the question and,

drafted for the person to decide at the M0 gate. Write "None" if there are none.

- [answered 2026-10-07 by Amirishetty Sai Vignesh] Stale read on eviction. The HLD lets an
  evicting node keep a readable copy until `WRITEBACK_ACK`, but has the home mark the page
  UNCACHED once it stores the data (home rule 5); another node can then be granted the page
  and write it while the evictor still reads old bytes. Options: the home keeps the evictor as
  a reader; the evictor discards at once and keeps the bytes in a buffer; leave as is. Answer:
  the home keeps the evictor as a reader. After `WRITEBACK` the page is SHARED with the
  evicting node as its one reader, so a later writer invalidates it first. This changes HLD
  home rule 5.
- [answered 2026-10-07 by Amirishetty Sai Vignesh] Order on `FETCH_INV`. HLD: write-protect,
  send, discard, wake. Plan M2-2: write-protect, send, wait for acknowledgement, discard, wake;
  the protocol has no acknowledgement for that data. Answer: the HLD order, no wait. M2-2's
  "no zap before the acknowledgement" check applies to eviction (`WRITEBACK`) only.
- [answered 2026-10-07 by Amirishetty Sai Vignesh] Still open #6. Between `WRITEBACK` and
  `WRITEBACK_ACK` a page is in none of the HLD's six states. A fourth in-flight state, or a
  mark on M? Answer: a fourth in-flight state, `M→I`. The document has three stable and four
  in-flight states, where the card says three and three.
- [answered 2026-10-07 by Amirishetty Sai Vignesh] Anti-thrashing hold window (AT-1): which
  requests wait while a writer's grant is held? HLD home rule 6 says "the next writer"; its
  fairness section says the page "is not taken back". Answer: only writers wait. A read is
  served at once.
- [for gate] S1 — form of the node machine: one `NEED_W` event for both kinds of write fault;
  a fault that finds the page already usable is answered with a wake; Rule 0 (replies are
  matched to the page's current request, others are dropped and counted).
- [for gate] S2 — M1-3's card lists only `I`, `S` and `I→S`, but the M1 gate has B read what A
  wrote and M1-4 has the home fetch from an owner, so in M1 a node must also take a write
  fault (`I→M`), hold `M` and answer `FETCH`. Those rows are marked M1. Alternative: move them
  to M2 and have M1's writer be the page's own home, which the hashing does not guarantee.
- [for gate] S3 — a `WRITEBACK` that arrives after the home took the page by `FETCH` or
  `FETCH_INV` is acknowledged and its data dropped. The HLD does not cover the case.
- [for gate] S4 — `ATOMIC_OP` on a shared page invalidates every read copy, the requester's
  included, and leaves the page UNCACHED. The plan says only "takes the page back if another
  node holds it". The model shows a stale read if the requester's copy is spared.
- [for gate] S5 — `W_LOAD`: a spilled page is read from disk off the network thread and
  returns as a `LOADED` event. Alternative: read it inline, which breaks the rule that the
  network thread waits only on epoll.
- [for gate] S6 — hold-window accounting: a transfer is a write grant to a node other than the
  last writer; more than the threshold within the period starts a window of
  `thrash.hold_initial`, doubling to `thrash.hold_max`; a transfer at or below the threshold
  resets it; `ATOMIC_OP` from another node counts as a writer. Also: AT-1 must report "the two
  tasks", but page requests carry no task. Proposed: report the two nodes and let each node's
  log name its task. Alternative: add the task ID to `WRITE_REQ` and `UPGRADE_REQ` in
  `docs/PROTOCOL.md`.
- [for gate] S7 — segment states `OTHER`, `SERVING`, `FROZEN`, `MOVED`, `ARRIVING`, following
  the leave order proposed as P11 in M0-5 (new map before migration). Changes if P11 does.
- [for gate] S8 — an "impossible" pair that occurs aborts the job with status `INTERNAL`.
- [for gate] S9 — a leaving node stops serving faults once it has written back its last page; a
  task still running on it stays parked until the process exits.
