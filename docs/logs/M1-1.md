## Decisions

<!--
Choices you made inside the card's scope, each with the reason. Not for points listed under
"Still open" in the plan: those are asked, never decided here. Write "None" if there were none.
-->
- **Two payload shapes, not one struct per opcode,** for the page messages: `PageIdPayload` and
  `PagePayload`, as `docs/PROTOCOL.md` section 7.2 itself defines them.
- **Only the M1 opcodes have codecs.** The card says so; M2 to M4 add theirs.
- **A decoded page points into the buffer it was decoded from,** so 4 KB is not copied twice.
- **One source file** for the header and all payloads; they share the reader and writer.

All local, 2026-10-07 (GCC 13.3.0, Clang 18.1.3). `unit.wire_test`, 6 cases:

- **Round-trip tests pass:** every M1 payload, including a full page and a zero page; a header
  re-encodes to the bytes it was decoded from.
- **Fixed byte sequences decode to the expected fields:** a 36-byte header (READ_REQ, RETRY,
  job, nodes, request, epoch, length 9, CRC `E3069283`), a page ID, a `SEG_MAP_ACK`, a
  `JOB_END` ("node 7 lost") and a two-member, three-segment `SEG_MAP`.
- **A corrupted payload is rejected:** `wire_check_payload` accepts "123456789" against that
  header, and returns `Errc::kProtocol` with one bit flipped and with one byte missing.
- Also rejected: wrong magic, version, opcode, over-long payload; payloads of the wrong
  length; a page whose data does not match `ZERO_PAGE`; a bad role; a segment map with a home
  that is no member, with no members, with nine, or cut short; a `JOB_END` with an unknown
  status or a message longer than its bytes.
